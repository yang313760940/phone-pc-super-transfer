# 0001 手机端改为原生录音 App，替代浏览器网页

- 状态：已接受（2026-11-24）
- 相关：规格 #4、实施票 #5–#10；本决定推翻此前「out of scope：不开发原生 APK」的边界。

## 背景

最初的 MVP 走「手机浏览器打开电脑局域网 H5 页录音上传」路线，已真机跑通并交付（server + web + 电脑端转写客户端）。此前的 out-of-scope 明确写了「开发或打包原生安卓 APK」，理由是追求最轻、无安装。

## 决定

手机端改为**原生 Android App（Kotlin）**，彻底替代浏览器录音页：在 App 内完成录音、发送到电脑、显示可复制文字、失败重试。电脑端 `server/` 与其转写、剪贴板、落地文件、`history.txt` 全部复用，不改动。

## 为什么

用户明确要求「安卓原生 App 彻底替掉浏览器网页」，不接受 WebView 套壳。原生 App 在麦克风权限、常驻、录音稳定性、无需每次开浏览器输 https 地址与信任证书上体验更好，符合自用场景。

## 代价与后果

- 需要安装 Android SDK + Gradle 才能构建（本机此前无 SDK）。
- 证书信任从"浏览器点继续"改为 App 内固定信任 `server/certs/cert.pem`（certificate pinning）。
- 网页 `web/index.html` 保留但不再是主入口；旧边界被推翻，属方向性转向。

## 替代方案（未采纳）

- Flutter：需装另一套 SDK，且与"原生 Kotlin"诉求重复。
- Capacitor/Cordova WebView 壳：最省事，但本质仍是网页，违背"彻底替掉浏览器网页"。
- PWA / 加到主屏幕：仍有浏览器与证书限制，非真 App。
